# sample

A generated full-body character — prompted as an adult woman with long wavy
hair in a cream blouse and a navy pinafore dress, standing with her hands
clasped in front of the waist — made to
be this repository's plain public fixture: base checkpoint, no LoRA, and a rig
the reference implementation built from its own proposal with no hand edit.
Its heavy inputs (the painting, the two images See-through was fed, and the
`full` and `head` See-through layer sets) live in the
[spine-parts-examples](https://github.com/firejune/spine-parts-examples)
repository, which also holds the generation record and the licence;
`bun run fetch-examples` copies them into `inputs/` here (gitignored). What is
tracked is the light half: `config.json` (the reference's config converted to
this schema, `src/config.ts`), `proposal.json` (what the proposer wrote — the
`propose` stage), and under `expected/` the reference implementation's outputs,
for the TypeScript stages to be compared against — `parts.json` (`assemble`;
its `visible_px`, `occluded_px` and `visible_not_projected_px`, and its
top-level `recomposite` block of uncovered holes, are this port's counts, which
the reference does not write, inserted from this port's own default build with
every reference value left as it was),
`rig.json` (the reference's, whose bones are all unturned; this port turns each chain link along its chain — issue #73 — so the built rig is compared through `flattenRig`, which turns every offset back, and matches it exactly), `motion.json` and `mesh_report.json` (`rig`), and `check.json` and
`gate_spine-html.txt` (`check`, the last being spine-rigc's gate lines); `check.json` is
regenerated by this port's `build`, because the reference has no judgement lines
— issue #11 — and again when the turned chains moved a judgement figure or two in
the third place through the runtime's float32 posing — issue #73 — and so is `motion.json`, whose blink holds 0.084 s where the
reference's held 0.04 s, less than one 12 fps frame — issue #32; its four hold-end
and open-end key times are the only values that differ from the reference's beyond the rounding of its float64 sums). Issue #119 (`assemble` clears a fringe below alpha 250 where the painting shows the part beneath it, which the reference did not) moved these from the reference's: `parts.json` holds this port's values for the 15 parts the rule touched — 276 px pushed back, each part's `fringe_pushed_back` list by holder, `opaque_px` and the three visibility counts taken after it, the boxes of `brow_r` (25 wide, was 27) and `iris_r` (19 wide, was 20), and `seam_override_px` one higher on `iris_r` — and this port's `recomposite` block (error px 4,359, was 4,512). `rig.json` holds this port's region offsets for `brow_r` and `iris_r` and this port's `hair_front` lattice (hull 56, was 54, with its uvs, weights and triangles), rebuilt on the 62 px the rule cleared from that part; `mesh_report.json` holds that mesh's hull and triangle count (200, was 202). `check.json` is this port's build of them (15 reported figures moved, every status as before). `sheets/` holds the reference's
contact sheets of the two layer sets and of the assembled parts (`sheet`).
